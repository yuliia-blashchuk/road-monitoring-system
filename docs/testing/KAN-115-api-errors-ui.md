# KAN-115. Показ помилок API в інтерфейсі

Мета: користувач бачить зрозуміле повідомлення українською і знає, що робити далі.
Він не бачить кодів HTTP, англійських системних текстів чи технічних деталей сервера.

## Як це влаштовано

| Файл | Що робить |
|---|---|
| `frontend/src/services/apiErrors.ts` | `requestApi()` - `fetch` з таймаутом 15 с і єдиною обробкою помилок; `ApiError` з видом помилки, текстом, полями й згодами, яких бракує |
| `frontend/src/components/ApiErrorMessage.tsx` | Блок повідомлення: заголовок, текст, список полів, кнопка «Спробувати ще» або посилання «Увійти знову» |
| `roadmapApi.ts` (KAN-109) | Спільний `request()` усіх сторінок (карта, форма заявки, картка, кабінети, сповіщення) працює через `requestApi()`; для завантаження фото й акта таймаут 60 с |
| `authApi.ts`, `auditApi.ts` | Вхід, реєстрація й журнал аудиту працюють через `requestApi()` |
| `AuditLogPage.tsx` | Показує `ApiErrorMessage` з повтором запиту |

Сторінки, як і раніше, показують `error.message`, тепер уже зрозумілий текст. Щоб додати заголовок і кнопку «Спробувати ще», замість `<p>{error}</p>` можна поставити `<ApiErrorMessage error={error} onRetry={…} />`.

## Які повідомлення бачить користувач

| Ситуація | Відповідь API | Повідомлення | Дія |
|---|---|---|---|
| Немає інтернету / бекенд вимкнено | запит не дійшов | «Немає зв'язку із сервером RoadMap. Перевірте інтернет і спробуйте ще раз.» | Спробувати ще |
| Сервер не відповідає 15 с | таймаут | «Сервер довго не відповідає. Спробуйте ще раз трохи згодом.» | Спробувати ще |
| Невірний пароль | 401 на вході | «Невірний email або пароль.» | - |
| Сесія завершилась | 401 | «Сесія завершилась. Увійдіть знову.» | Увійти знову |
| Немає прав | 403 | текст сервера («Недостатньо прав для цієї дії») або текст сторінки | - |
| Бракує згоди водія | 403 з `missing_consents` | текст сервера з переліком згод зрозумілими словами | - |
| Помилка в одному полі | 422 | текст сервера для поля, напр. «Ділянка не обслуговується» | - |
| Помилки в кількох полях | 422 | пояснення сервера через «;», а якщо вони англійською - «Перевірте поля: Пароль, Email.» | - |
| Системний текст англійською | 422 від Pydantic | «Перевірте поле «Пароль».» замість «String should have…» | - |
| Не знайдено / конфлікт | 404 / 409 | текст сервера, напр. «Ви вже підтвердили цю заявку» | - |
| Забагато заявок | 429 | «Перевищено ліміт: не більше 10 заявок на годину» | Спробувати ще |
| Збій сервера | 5xx або не JSON | «На сервері сталася помилка. Спробуйте трохи пізніше.» | Спробувати ще |

## Тест-кейси

| TC-UI-03a | 422 українською, кілька полів | пояснення сервера через «;» | Пройдено |
| TC-UI-04 | 403, бракує згод | перелік згод українською | Пройдено |
| TC-UI-05 | 401 з текстом про токен | «Сесія завершилась. Увійдіть знову.» | Пройдено |

| TC-UI-10 | Таймаут | повідомлення про таймаут | Пройдено |

| TC-UI-12 | Успішна відповідь | повертається тіло | Пройдено |
| TC-UI-13 | Англійська помилка JavaScript | не показується користувачу | Пройдено |

Ручна перевірка в браузері (бекенд і фронтенд запущені локально):

- вхід з невірним паролем → «Невірний email або пароль.»;
- журнал аудиту, кінець періоду раніший за початок → блок «Перевірте дані» з підказкою про фільтри;
- журнал аудиту, сервер повернув 500 → «Помилка сервера» і кнопка «Спробувати ще», після повтору журнал завантажився.
